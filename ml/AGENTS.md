# กฎเพิ่มเติมสำหรับ `ml/` (ใช้ร่วมกับ `AGENTS.md` ที่ root)

ต้นแบบ pipeline ข้อมูลธุรกรรม → ML → Monte Carlo → ยอดใช้ได้วันนี้ + โอกาสเงินพอ ด้วย **ข้อมูลจำลองทั้งหมด** รายละเอียดอยู่ใน `ml/README.md`

## Environment

- ใช้ Python ใน `ml/.venv` เสมอ ไม่ใช้ Python ของระบบ และไม่ `pip install` นอก venv
- สร้างครั้งแรก: `uv venv .venv && uv pip install -p .venv/bin/python -r requirements.txt` (รันใน `ml/`)
- เพิ่ม dependency ต้องแก้ `requirements.txt` ด้วย

## คำสั่ง (รันใน `ml/`)

```bash
.venv/bin/python -m unittest discover -s tests   # หรือ npm run check:ml จาก root
.venv/bin/python run.py --quick                  # 60 คน เช็กเร็ว → output/quick/
.venv/bin/python run.py                          # 300 คน ~1 นาที → output/
```

`output/` ไม่อยู่ใน git สร้างใหม่ได้ทุกครั้ง

## การรายงานผล

- ข้อมูลจำลองถูกสร้างโดยทีม รูปแบบที่โมเดลจับได้เป็นสิ่งที่ใส่เข้าไปเอง ผลจึงพิสูจน์ว่าระบบทำงานถูกตามตรรกะ ไม่ได้พิสูจน์ความแม่นกับข้อมูลจริง ต้องติดป้ายว่าเป็นข้อมูลจำลองทุกครั้ง
- เทียบผลกับ baseline `usual` (ผู้ใช้ใช้จ่ายตามปกติโดยไม่มีแอป) เป็นหลัก ไม่ใช่แค่ `even` (หารเท่า ๆ กัน) เพราะกรรมการจะถามว่า "เทียบกับไม่ทำอะไรเลยล่ะ"
- รายงานทั้ง `ml` (budget ที่ไม่เกินการใช้จ่ายปกติ) และ `mc_noml` (Monte Carlo ไม่มี ML) อย่างตรงไปตรงมา อย่าเลือกเฉพาะตัวเลขที่ดูดี
- ตัวเลขทุกตัวที่จะไปอยู่ในสไลด์หรือเว็บต้องรันซ้ำได้จาก `run.py` หรือโค้ดใน `krunway/` ห้ามคำนวณมือหรือแก้ตัวเลขใน output
- เปลี่ยน seed จำนวนผู้ใช้ หรือนิยาม method แล้ว ต้องบอกว่าตัวเลขเดิมในสไลด์หรือเอกสารอาจไม่ตรงแล้ว
